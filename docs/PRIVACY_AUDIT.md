# 发布隐私检查

当前源码的隐私整理将昵称示例、注释中的账号信息、测试身份与开发机路径替换为中性数据；应用标识统一为 `io.agentcockpit.desktop`。每次发布仍需重新扫描最终文件，不能把历史检查当作当前版本的保证。GitHub 项目地址、本项目公开署名和第三方原许可证的版权人信息有来源标识用途，应保留。

桥接程序通过环境变量、用户目录和程序相邻目录查找，不再依赖开发者的绝对目录。设置、账号和保管箱仍使用原有数据根；应用标识变更可能需要重新固定任务栏图标，已有快捷方式可在常规设置中重新创建。

## 每次发布

1. 经 `agsync build` 运行 `python tools/privacy_check.py` 和 `python tests/privacy-check.test.py`。规则发现可疑内容时只报告文件、行号和类别，不打印原文。
2. Rust 构建通过 `python tools/private_build.py build --release`，测试通过 `python tools/private_build.py test`，均作为 `agsync build` 的命令参数。脚本将编译路径映射为中性目录，减少二进制中的开发者路径。
3. 对最终 EXE 执行 `python tools/privacy_check.py --binary <exe>`。已知个人关键词保存在本机被忽略的 `.agent-sync/private-terms.json`，不进入公开包。
4. `python tools/export_public_source.py <仓库外的目标.zip>` 生成只包含可发布文件的源码快照。没有 `.git`、本机配置、日志、旧 EXE、备份或账号目录。

上述步骤不是一次执行就能确认远端仓库“已清理”。当前源文件、Git 历史、Releases 附件、Issue/评论、截图与其他人的 fork/下载副本是不同对象。本次文档审阅不改写或推送 Git 历史，也不证明旧公开副本已删除。

## 检查范围和限制

规则检查覆盖当前可发布源码与资源中的个人目录、非示例邮箱、常见密钥形式和本机指定的隐私关键词。模拟数据中少量可确认的虚构密钥与编码测试邮箱有精确白名单，新密钥不会因处于同一文件而被放行。二进制检查覆盖已知关键词的 UTF-8、UTF-16 编码；这不是通用的秘密发现保证。

WorkBuddy 运行时密钥恢复属于本机只读操作：程序读取客户端 `keyblob`，扫描正在运行的官方主进程，并以 keyblob 的 GCM 解封结果验证候选。通过验证的密钥只写入 DPAPI 保管箱；源码、日志、测试夹具和发布包均不得包含真实值。发布前仍须对最终源码和二进制执行隐私门禁。

旧 Git 提交已发现隐私残留，改当前文件不会删除历史。历史重写、远端强制推送及删除旧 Releases 是独立操作，必须在明确目标后处理。对外分发应使用上述无历史快照或新建的干净仓库，不能将原仓库连同 `.git` 打包上传。本机用于回滚的旧程序、内部交接资料及用户账号数据不属于公开源码包。

正式公开前还应人工检查截图、视频、提交作者信息、发布附件与 Issue 中的日志。若旧版本曾包含有效凭据，需要在对应服务撤销或轮换；清除源码不能撤回已经下载的副本。

第三方许可证和版权署名不是应删除的测试身份；保留要求见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。若扫描器命中某份原许可中的公开署名，应核实并做精确例外，不能改写版权人或给整个目录放行。
