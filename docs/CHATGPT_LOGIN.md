## 功能对应

| 方式 | AgentCockpit 操作 |
|---|---|
| 官方客户端登录 | 准备临时配置 → 打开官方客户端 → 等待登录完成 → 关闭临时客户端 → 读取最终登录信息 → 清理临时配置；成功后登记新账号 |
| OAuth 浏览器授权 | 调用已安装的官方 Codex 登录组件，显示授权进度、链接，支持复制和无痕窗口 |
| 设备码授权 | 官方 `codex login --device-auth`，在界面显示官方提示和设备码 |
| 手动回调 | 仅提交给本次官方登录进程的本机监听地址，校验端口、路径、state 和 code |
| Token / JSON | 支持官方 auth.json、tokens 对象、ChatGPT session/accessToken、access token 和 refresh token |
| 文件导入 | 在界面选择 JSON/TXT 文件，8 MB 上限；凭据不会进入通用账号表单 |
| 批量导入 | JSON数组或每行一个令牌，按指定前缀创建新账号；预先检查重名，逐个展示结果，成功项才登记卡片 |
| API Key | Key 走官方 CLI 的标准输入；可选 Base URL 只写入该账号的配置 |
| 本机导入 | 只读默认或用户选择的 auth.json，写入目标独立账号；系统凭据库格式应通过官方登录组件完成授权 |

浏览器与设备码授权可取消和重试，十分钟未完成会结束登录组件，保留目录。凭据导入后的实际服务可用性以官方客户端验证为准。

官方客户端登录使用 `.agent-cockpit/chatgpt-temp-login/<会话编号>`，内含独立浏览器资料、运行目录和归属标记。先等临时客户端退出，再重新读取最终凭据。导入失败保留临时配置，可重试；导入成功、清理失败时重试只清理，不重复创建卡片。重启管理器后可以恢复未完成会话。取消只处理本次临时客户端和标记匹配的目录。

临时运行配置显式指定 `cli_auth_credentials_store = 'file'`、`features.secret_auth_storage = false`。读取 `auth.json`，不搜索、解密或删除其他账号的系统凭据库。现有系统凭据库账号的本机导入，应改用官方登录重新授权。

## 对话和项目

添加账号默认复制本机已有对话和项目的快照，可以明确选择空白历史。仅复制会话文件、历史索引、项目元数据和对应 SQLite 数据库；SQLite 使用只读连接的一致快照，包含已提交的 WAL 内容。只在副本中调整 rollout 路径及本地主机标识，保留会话文件原始字节，以免破坏历史分页偏移。已有对话的目标不会被覆盖。

历史快照不包含 `auth.json`、供应商配置或浏览器缓存。API Key 及中转站 Base URL 由用户为各账号单独输入。每个账号使用新分配的固定目录编号，删除卡片后重新使用原名称也不会复用旧凭据目录。历史在创建时复制，各个窗口后续产生的对话暂不实时同步。

会话文件被本机压缩为 `.jsonl.zst` / `.jsonl.gz` 时，保留压缩原文件，在副本中恢复未改写的 JSONL 内容。真实项目及工作树继续指向原位置。以最新根数据库的归档状态为准，已归档且原文件缺失的旧索引仍保留，并显示缺失数量；未归档对话缺少可恢复内容时停止复制并报错。

## 目录约束

- 原有默认资料只做原位登记。启动本机原有账号时保留原有登录和默认运行数据。
- 新账号分配新的普通目录，复制历史快照，独立保存新登录；原目录保持原位。
- 新账号浏览器资料通过 `--user-data-dir` 与 `CODEX_ELECTRON_USER_DATA_PATH` 隔离；运行与凭据通过独立 `CODEX_HOME` 隔离。
- Windows商店版通过已注册的包身份启动，核对安装位置和清单入口，再由隐藏的包内辅助进程传递实例环境。启动未确认时直接报错，不回退到默认资料。
- 禁止 ChatGPT 的 Junction 换号、自动目录归位、缓存共享和覆盖恢复；启动体检只报告旧链接，不自动修复。
- 通用凭据登录、退出、改绑和文件换号旧入口也会拒绝执行，防止绕过专用登录页的保护。
- 检查资料路径及其父目录，发现链接时停止启动或写入，提示先处理旧链接。
- 改名保持实际目录不变。移除账号只移除登记，保留浏览器资料、登录凭据和对话。
- OAuth 凭据不会沿用自定义 API 供应商地址；原有凭据写入失败时恢复原配置和凭据。
- 不自动修改已存在账号的资料目录、原默认资料备份或安装位置。

## 验证

按 `.agent-sync` 协议登记任务后，通过 `agsync build --test-cmd` 调用 `tests/check-chatgpt.ps1`，覆盖后端和界面行为。测试使用合成凭据及临时目录；正式登录仍由用户在官方授权页面完成。

2026-10-26 实机检查：本机商店版 26.1021.3705.0 直接执行 ChatGPT.exe 时仅生成浏览器资料，未初始化独立运行目录；改为注册包身份后，两个临时实例各生成35项浏览器资料及独立 sqlite、.codex-global-state.json 等运行文件。默认 auth.json 的 SHA-256 校验值相同，默认资料仍为普通目录。临时实例已经结束，测试目录保留以便核对。

六步流程改造的验证包括关闭/读取/导入/清理顺序、失败时保留凭据、清理目录归属、界面轮询和取消、SQLite WAL 快照、路径重写及已有对话保护。`AGENTCOCKPIT_OFFICIAL_SMOKE=1` 可通过同一检查入口打开一个临时官方客户端，验证取消清理、默认凭据不变和原有客户端继续运行。真实账号的浏览器、设备码授权及令牌续期需要有效账号交互，未代替用户完成。

2026-10-27 实机检查已通过临时官方窗口启动、取消、关闭和清理，以及旧测试会话恢复清理。默认 `auth.json` 字节保持一致，原有默认窗口继续运行。历史快照保留130条对话索引、12个项目、116个原始会话文件，并恢复101个压缩文件；23条已归档记录的源文件原本缺失，索引仍保留。19项历史检查（含实机快照）及19项界面检查通过。

进程归属必须显式读取命令行：sysinfo 0.33 默认刷新不含 `cmd`，现改为请求 `ProcessRefreshKind::with_cmd`。空命令行及无法解析的独立目录参数均不会被认领为默认实例，结束窗口仍按完整资料路径匹配。

## 实例卡片与日常操作

2026-10-27 后续重构将实例设置整理为：概览、额度与用量、运行管理、对话与项目、文件位置、登录管理、移除账号。添加成功后返回账号列表并定位新卡片；已登录账号的登录管理先展示当前身份，明确选择更换后才展开表单。文件位置使用独立块布局，长路径可换行、复制与打开。

API 供应商的显示名称采用卡片名称，内部供应商编号保持固定。已有客户端可在重新打开后读取新名称。修改名称保持实际目录及登录凭据原位。

Plus 通过固定官方 `backend-api/wham/usage` 获取5小时及每周窗口；API余额兼容供应商同源token/display、billing及usage接口，AIwelink实机采用 `/v1/usage`。卡片与额度页共用真实数据、更新时间和刷新动作。只有曾成功读取的数据才可以显示缓存；未支持、连接失败和未读取分别显示，不推算不存在的余额。

## 项目列表迁移状态

现有实例的修正先检查来源、创建批次、用户编辑、选中/置顶及对话引用。仅处理可确认由旧迁移生成、没有对话的多余登记。运行中仅将计划记入卡片，下次从卡片启动前确认旧窗口已退出，再备份 JSON 与 SQLite 后修正。用户编辑或新增对话会停止对应修正；物理项目文件和会话文件不删除。

`AGENTCOCKPIT_CARD_MAINTENANCE=1` 显式校正已有API显示名、安排项目修正；`AGENTCOCKPIT_QUOTA_SMOKE=1` 使用已登记账号检查实际额度，仅记录数值与状态；`AGENTCOCKPIT_LAYOUT_SMOKE=1` 用 Chromium 对实际 HTML/CSS/JS 的7个菜单进行宽窄窗口及长路径检查。均由 `agsync build --test-cmd` 调用检查脚本执行。

上游是功能与机制参考，临时登录和历史复制分别参考 `codex_temp_login.rs`、`codex_instance_creation.rs`、`codex_profile_copy.rs`，按本项目结构独立实现。用户已有的账号登记仍按原路径读取，发现不安全目录时停止操作并提示。

## Windows 任务栏、托盘与恢复窗口

驾驶舱进程和主窗口显式使用 `com.renlu.agent-cockpit`，本人快捷方式也写入相同 AppUserModelID。部署经桌面 Shell 启动，避免从 Codex 商店包内的命令行继承 ChatGPT 身份而在任务栏混组。Windows 将图标收入 `^` 溢出区不等于没有托盘图标，用户可以将其拖到常显区。

驾驶舱托盘右键的“打开 ChatGPT 窗口”按账号列出所有已登记窗口；卡片及运行管理页也提供“打开窗口”。已有进程先按完整资料目录寻找并恢复自己的真实主窗口，排除工具窗和 IPC 辅助窗。主窗口已销毁时，用同一份资料和登录目录再次激活客户端，不先执行离线历史修复或覆盖凭据。官方客户端自己的托盘图标仍由官方管理，不能作为所有多开账号的统一入口。

## 首次沙箱初始化

`codex-windows-sandbox-setup.exe` 是官方 Windows 沙箱初始化组件。使用需要管理员初始化的沙箱时，每个新的独立 `CODEX_HOME` 可能分别出现一次 UAC；沙箱内执行的命令仍受沙箱限制。AgentCockpit 保留各目录的初始化标记，不复制其他账号的沙箱安全身份，也不通过降低权限设置来隐藏提示。

2026-10-27 实机检查：三个已登记账号分别于09:39、09:43、09:54完成一次初始化，后续启动未见重复初始化记录；两处官方 setup 可执行文件签名均为有效的 OpenAI OpCo, LLC，文件校验值一致。若同一张卡后续每次启动仍出现 UAC，应核查那次的官方 setup 日志。官方说明：https://learn.chatgpt.com/docs/windows/windows-sandbox 。
