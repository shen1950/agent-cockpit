# 桌面临期提醒：浮窗与宠物双方案

状态：交互设计与可操作原型，尚未接入真实桌面窗口和账号数据。

## 共同提醒规则

两种入口共用提醒清单、已读状态和稍后提醒时间，可单独启用或同时保留。默认关闭，由用户在设置中开启。数据来自驾驶舱现有额度缓存，不单独读取凭据，不因动画额外请求接口。

有准确时间的资源包按 `now < expires_at <= now + 24h` 纳入清单；已经过期或剩余为零的资源包不再提示。跨午夜仍用连续 24 小时计算。只有日期时，“今天到期”单列，标注“平台未提供具体时间”，不伪造倒计时；日期为明天的列入“明天到期，时间待确认”，不能声称一定在 24 小时内。日期按平台时区解释，未知时使用本机时区并注明。

每条显示产品、账号别名、资源包名称、剩余额度与单位、到期时间、数据更新时间。不同单位不可直接相加；同一账号多个资源包展开查看。主摘要显示账号数和资源包数。读取失败保留上次数据并标记“待刷新”，不把失败当余额为零。无限期、缺失或无法解析的日期不参与倒计时，另显示“到期时间未知”。

提醒仅在进入 24 小时范围、进入最后 2 小时、用户设置的稍后时间到达时触发一次。同一事件跨两个入口去重；默认无声音、不抢焦点，每账号可“今天不再提醒”，全局可静音。休眠唤醒、系统时间变化、换屏和时区变化后重新计算。未来扩展便签时继续使用相同提醒调度。

## 方案一：可贴边的提醒浮窗

默认宽度约 320 px，高度适应屏幕；无边框、圆角、铜橙强调色，支持浅深主题。标题栏可连续自由拖动，禁止图片原生拖拽与文字选择打断 pointer capture。拖近当前屏幕上下左右任一可用边缘 20 px 时吸附；任务栏所在的一边禁止吸附，角落选择剩余可用边中最近的一边。鼠标在窗口内或正在拖动时保持展开，离开 160 ms 后以 240 ms 缓出动画滑入边缘，无需点击空白处。收起默认按 TieZ 方案处理：卡片保持原尺寸滑出屏幕，只在可用边缘留 3 px 细缝，靠近细缝悬停 120 ms 或点击即展开。设置里的“贴边提示条”开关打开后，收起改为在边缘保留 24 × 86 px（横边 86 × 24 px）的可见标签，显示临期数量，悬停或点击展开。右上角依次为钉子和 × 图标按钮：钉子固定展开，高亮表示已固定；× 关闭浮窗入口。顶部“提醒浮窗”或“同时预览”可重新打开。

键盘导航时保留聚焦控件所在窗口，方向键微调位置，Esc 收回；鼠标点击按钮留下的焦点不阻止自动收起。减少动画开启时立即切换状态。悬停进入时取消收起计时，展开时保留吸附方向，移走后再次收起；从边缘拖走则解除吸附。

展开后先展示“今天 / 24 小时内”，再按到期时间排序。每条的“去使用”打开驾驶舱对应账号详情，不能自动切换正在使用的账号，也不能自动消耗积分。底部有“刷新”“稍后 1 小时”“全部查看”。无临期时显示“暂时没有即将到期的积分”，不显示空白浮窗。

位置按显示器标识和工作区相对坐标保存，兼容多屏、DPI、任务栏位置变化；显示器拔掉后回主屏可见区。置顶单独开关；全屏应用期间自动收回，默认不覆盖游戏或演示。关闭浮窗只关闭这个入口，驾驶舱托盘继续运行。以后在清单旁增加“便签”标签，可新建文本、勾选清单、设置提醒，复用贴边和固定位置行为。

## 方案二：圆形悬浮球与独立桌宠

原来的方形图标伙伴改成约 80 px 的圆形悬浮球，清楚的铜色圆周、简化导航标记，光标移动时有轻微倾斜与高光偏移。支持整个球连续拖动、四边收起、任务栏避让；气泡随球定位，边缘空间不足时翻转并保持可见。拖动不触发点击，点击才打开气泡。尊重减少动画设置。

悬浮球的 × 按钮平时隐藏，鼠标停在球上时显示；键盘聚焦到球内时同样显示，便于 Tab 操作；触屏设备保持可见。关闭后同时隐藏球、气泡和球的边缘标签，保留提醒浮窗。关闭按钮与拖动按钮是并列控件，避免嵌套按钮和误触拖动。顶部“圆形悬浮球”或“同时预览”可恢复。

角色桌宠独立设计，不把图标当作角色。候选为铜翼小鼯、巡航小鳐、时间寄居蟹、折纸信使，完整外形、动作和绘图提示词见 `desktop-pet-concepts.md`。使用注视跟随、轻歪头、被拖起和贴边探头的动作；未来可与悬浮球切换，提醒状态共用。当前未生成或接入这些角色动画。

同一到期事件由最后使用的入口显示气泡，另一个入口只更新徽章。同时开启时不重复弹消息。气泡最多三行，8 秒后淡出；鼠标停留或键盘聚焦时暂停。系统减少动画设置开启时关闭循环浮动；电池模式降低动画帧率，隐藏时停止绘制。伙伴保持可关闭、可静音，不评价用户的使用习惯。

## 工程落地顺序

1. 独立实现提醒选择器及测试，覆盖精确时间、日期、跨日、时区、过期、零余额、缓存过旧和单位分组。
2. 新增 Tauri `reminder-panel` 窗口，只授权位置、显隐、尺寸与限定账号跳转，复用后端事件，不通过前端高频轮询。
3. 浮窗实现多屏吸附与位置恢复，完成失焦、全屏和键盘交互验证。
4. `reminder-pet` 复用同一提醒事件，实现轻动画和静音。宠物为 AgentCockpit 本机窗口，不使用 ChatGPT Pets 服务。
5. 用户试用两个入口后，再增加便签存储及迁移。便签保存到用户数据根，禁止写进代码仓库或发布资源。

当前原型 `desktop-reminders-prototype.html` 使用虚构账号和余额，演示两入口自由拖动、上下左右收起/展开、钉住、气泡跟随、静音与稍后提醒。它是浏览器内的桌面模拟，不会实际创建置顶桌面窗，也不会读取真实账号；任务栏位置由下拉菜单模拟。真实 Windows 窗口落地时需用系统显示器工作区与任务栏位置（含自动隐藏任务栏）检测，而不能沿用演示下拉值。

## 本轮参考实现

阅读了用户提供的 TieZ-GuLing 本地源码，对应项目为 [tiez-clipboard](https://github.com/shen1950/tiez-clipboard)。参考位置为 `src-tauri/src/app/setup.rs` 的 `start_edge_docking_monitor` 和 `src/features/app/components/AppHeader.tsx`。本地版本通过鼠标位置、按键状态和固定状态决定收起，展开后保留吸附方向，顶部使用 Pin/PinOff 与 X 图标。

此原型借鉴这些交互规则，独立使用 DOM 指针事件和 CSS transform 实现；160/120 ms 延时、240 ms 动画、底边吸附和模拟任务栏避让是本原型的设计参数，不声称来自 TieZ。
